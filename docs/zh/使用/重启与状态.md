# 重启与状态

## 模块重启

模块替换程序文件后可请求重启自身：

```js
await ctx.requestReload();
```

流程：

1. 核心验证新代码可加载
2. 验证失败：旧实例继续运行，返回 false
3. 验证通过：停止旧实例（其公开对象注销），用已验证代码启动新实例
4. 返回新实例是否处于运行态：启动被跳过（停机中、启动中、禁用、超时锁定）或新实例启动失败返回 false

返回 false 覆盖三种情形：新代码验证失败（旧实例继续运行）、启动被跳过（旧实例已停）、新实例启动失败（旧实例已停）。需要区分时查 getModule(模块名).status：返回 false 且状态为 running，说明旧实例仍在运行。

状态保存与恢复是模块的职责，核心不迁移任何状态。

## 模块状态

模块状态四个取值：

| 状态 | 含义 |
| --- | --- |
| stopped | 停止，未运行 |
| starting | 启动函数尚未返回 |
| running | 运行中 |
| failed | 启动失败 |

启动时间与失败原因不在状态里保存：module-start 与 error 日志带时间戳与详情，查日志即可。

## 启动超时

YAML 声明 startTimeoutMs 后，超过时限核心放弃等待、标记失败，该模块不再因事件自动重试。手动启动、CLI 指令、配置加载、配置更新、重启请求可解除。
