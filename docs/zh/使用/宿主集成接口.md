# 宿主集成接口

宿主代码创建与操作核心的入口（相对命令行方式，这里是代码调用方式）。

## 入口函数

- createCore(options)：构造核心，不启动
- startCore(options)：构造并立即启动，返回已启动的核心

```ts
import { startCore } from './src';
const core = await startCore({ moduleDir: './modules' });
```

## 核心选项

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| moduleDir | ./modules | 模块文件夹路径 |
| logFile | ./logs/event-stream.log | 日志文件路径；同一路径只允许一个核心实例使用，重复使用抛错 |
| watch | true | 是否轮询监听模块文件夹变化 |
| pollIntervalMs | 200 | 监听轮询间隔（毫秒） |
| logToConsole | false | 是否把日志同步输出到控制台 |
| guardProcess | false | 是否捕获未处理的异步失败与未捕获异常，只记日志、不让进程退出 |
| defaultStartTimeoutMs | 0 | 全核默认模块启动超时（毫秒），0 或未配置 = 不设超时 |
| maxLogMemoryEntries | 20000 | 日志内存保留条数上限 |
| stopTimeoutMs | 20000 | 停机等待全部模块返回已关闭的时限（毫秒） |

根配置文件 hearth.yaml 的 core 段由命令行入口 src/hearth.ts 读取：只有 moduleDir、logFile、watch、logToConsole 在其中生效，相对路径按配置文件所在目录解析。其余选项（pollIntervalMs、guardProcess、defaultStartTimeoutMs、maxLogMemoryEntries、stopTimeoutMs）经 createCore/startCore 的选项设置。

## 核心方法

生命周期：start()、stop()、started。

模块管理：startModule(name, reason?)、stopModule(name)、reloadModule(name)、rescanModules()（返回是否真正执行了扫描；停机中或上一次扫描未完成时返回 false）。

事件与消息：sendEvent(name, data?, source?) 产生事件；sendTo(target, data?, source?) 点对点发送；sendDirected(targets, name, data?, source?) 按指定目标或全部广播直接投递事件，目标无需声明监听、不经启动比对（CLI send 指令的底层能力）。

公共对象：exposeObject(name, owner, value)、unexposeObject(name, owner)、object(pattern)。

查询与日志：listModules()、getModule(name)、logModule(name, ...parts)。

## 模块状态查询

listModules() 返回全部模块（name、config、status）；getModule(name) 返回单个模块。状态四个取值：stopped、starting、running、failed。
