# 模块配置

模块由 YAML 配置文件与程序文件组成。YAML 声明模块的身份、程序位置与事件关系。

## 字段

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| name | 必填 | 模块名，全局唯一，也是事件来源段与对象名第二段的来源；不能含冒号（:） |
| file | 必填 | 程序文件路径，相对 YAML 所在目录；可指向模块文件夹之外的目录 |
| startEvents | 无 | 事件模式列表，出现其中事件时核心启动模块 |
| listen | 无 | 事件模式列表，出现其中事件时核心向模块转发事件 |
| enabled | true | 是否启用；运行中改为 false 则停止模块 |
| startTimeoutMs | 无 | 模块启动超时（毫秒），超过时限核心放弃等待并标记失败 |
| config | 无 | 自定义配置，透传给模块经 ctx.config.config 读取 |

## 示例

```yaml
name: greeter
file: ./greeter.cjs
startEvents:
  - "core:startup"
listen:
  - "*:greet"
enabled: true
startTimeoutMs: 5000
config:
  threshold: 100
```

## 事件模式

startEvents 与 listen 的值是事件名模式，支持通配符：

- * 匹配任意字符序列
- ? 匹配单个字符
- 其余字符按字面匹配

模式匹配完整事件名（来源:事件名）。响应任意来源的同名事件写 *:事件名段。

## 配置热更新

- 新增 YAML：注册模块
- 内容变化：更新配置与转发表，运行中的模块实例与代码不变；模块经 ctx.config 读取新值
- 删除文件：停止并移除模块
- 解析失败的 YAML：记日志，下一轮重试
- 同名模块：拒绝注册，被拒文件持续重新请求

## 目录规则

- 每个模块一个子文件夹，文件夹内放 YAML 与程序文件
- 也支持把 YAML 直接放在模块目录顶层
- 只识别这两层，不递归更深目录
- 跳过 node_modules 与隐藏目录
