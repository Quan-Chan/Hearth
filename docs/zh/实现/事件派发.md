# 事件派发

## 事件名两段式

事件对象两个字段：name（完整事件名）与 data（内容）。完整事件名 = 来源:事件名段，来源段由核心在 dispatch 中按调用方拼装：

- 模块发出：模块名（ModuleContext.sendEvent 传 moduleName）
- 核心自产：core
- 宿主直接调用：external（sendEvent 的 source 参数）

模块无法伪造来源段：模块通道的来源固定为自身模块名。

## 比对索引

启动条件存于 startIndex，监听条件存于 listenIndex，两套索引结构相同，由两个概念组成：

- 精确表：无通配符的条件，事件名相等即命中，字符串比较，零正则，O(1)
- 通配列表：含通配符的条件，事件到达时逐条正则比对

重建时遍历全部条件：不含 * 与 ? 的进精确表，含通配符的编译进通配列表（复用模式编译缓存）。

模块启停不触碰索引，配置变更时全量重建。

索引决定先测哪些条件，条件怎么匹配由 EventMatcher 的通配符规则单独定义，两者独立。

## 简化记录

索引此前由五个概念组成：精确表、前缀桶、全局桶、溢出表、字节预算。本次简化：

- 前缀桶与全局桶：按首字面分桶少测条件的优化，移除后通配条件逐条比对
- 溢出表与字节预算：预算耗尽后的降级路径与参数链（选项、记账、下限、统计、调整指令），整体删除
- 保留：精确条件 O(1) 命中、模式编译缓存、两套索引、配置变更重建

最坏情况（大量通配条件逐条测）与原溢出路径持平，且成为确定行为而非预算耗尽后的分支。

## 派发顺序

dispatch 的步骤：

1. 拼装完整事件名
2. startIndex 命中未运行且启用的模块，按加载顺序逐个启动（启动为 await 串行）
3. listenIndex 命中运行中且实现 onEvent 的模块，逐个投递
4. 无人命中记 event-drop

同一事件双角色：对未运行模块是启动信号，对运行模块是工作指令。

## 定向投递变体

sendDirected 直接按指定目标投递事件：目标无需声明监听、不经启动比对、不进索引路由。targets 为 null 时广播给所有运行中且实现 onEvent 的模块。事件名同样拼装为两段式。CLI 的 send 指令调用它。

## 失败隔离

deliverTo 逐个 await 投递，单模块 onEvent 抛错只记 error 日志，继续投递其余。
