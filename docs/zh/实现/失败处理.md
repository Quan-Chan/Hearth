# 失败处理与守护

## 钩子调用点隔离

四个钩子调用点（start、stop、onEvent、onMessage）各自独立捕获异常：

- start 抛错：模块置 failed，记 error，不打断事件派发
- onEvent 抛错：记 error，继续投递其余监听者
- stop 抛错：记 error，模块仍视为已关闭
- onMessage 抛错：记 error，送达回执仍为 true

## 进程守卫

guardProcess（默认关闭）开启时：

- 注册 unhandledRejection 与 uncaughtException 全局处理器
- 捕获后写入全部开启核心的 error 日志，进程不退出
- 多个开启核心共享一次安装

未开启时，模块私下的未处理异步失败按 Node 默认行为杀死进程。

## 停机冻结

stoppingFlag 置位后：外部事件、定向信息、配置变更均被拒绝；停机期间模块调用发送接口抛“正在关闭”错误。文件面由 watcher.stop() 冻结，防止停机途中新配置被加载。
