# 场景：公共对象共享

模块公开对象，其他模块拉取同一对象引用，直接修改，内容对所有持有者即时可见。

## 流程

1. 模块 A 在 start 中调用 exposeObject('items', {...})，核心拼出三段式完整名 public:A:items 并映射该对象，拥有者记为 A，存引用不拷贝。
2. 模块 B 按完整名或通配符调用 object('public:A:items')（或 object('public:A:*') 拿映射）取得同一对象引用并修改。
3. 任何读取方立即看到变化，二次获取恒为同一对象。
4. 核心停止模块 A：
   - stop() 返回后 status 置 stopped
   - removeOwner 注销 A 的全部映射
   - 记 module-stop 含清理名单
5. 此后 object('public:A:items') 抛"公共对象不存在"；持有旧引用的消费者仍可写，核心看不见。
6. A 重新启动：exposeObject 公开全新对象，旧数据不残留。

## 边界

- 注销后写入不被核心看见，无任何日志，重启后数据永久消失（见 已知问题 12）。
- 无快照活引用：任何持有者随时改变所有人看到的内容，读取方须自行拷贝。
- 对象名不可改名：改名等于注销再公开。
- 重名即抛错：同一拥有者重复公开也抛错，start 里重复公开导致模块 failed（见 已知问题 14）。
- 消费者拉取抛错被投递隔离为一条 error。
- 核心层 API 的拥有者参数可被持有核心句柄的代码冒认；模块上下文层强制为模块名。
- 启动被作废的实例在 await 之后执行的 exposeObject 留下残留映射，直到该次启动返回时按拥有者一并注销（见 已知问题 12）。
- 无对象级审计：谁在何时写了什么不可追溯。
- 内容无界增长、不持久化（见 已知问题 13）。
