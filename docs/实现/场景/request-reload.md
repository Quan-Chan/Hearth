# 场景：请求重启

模块替换代码文件后调用 requestReload()，核心验证新代码并重启该模块。

## 流程

1. 模块替换代码文件，调用 ctx.requestReload()。
2. 前置检查：未知模块或未启动抛错；停机中、重启中、禁用记 module-skip，返回 false。
3. 加载并验证新代码，校验项：
   - 文件存在
   - 清缓存加载
   - ESM 动态 import
   - 工厂求值
   - 导出必须是对象
4. 验证失败：记 error，旧实例继续运行，返回 false。旧实例的状态、数组、事件接收全部不变。
5. 验证通过：记 module-restart，停止旧实例（stop() 返回即已关闭），注销其公开数组，记 module-stop。
6. 用已验证的代码启动新实例，返回 true。

## 边界

- 验证只覆盖可加载，不执行 start()：start 抛错的坏代码通过验证，旧实例已停，新实例 failed，reloadModule 仍返回 true。
- 停旧阶段无超时：stop() 悬挂则 requestReload 永不返回（见 已知问题 4）。
- 公共数组在停旧到启新的窗口消失，期间 array() 抛错（见 已知问题 12）。
- 重载后数组是新对象，旧引用失效。
- 验证失败污染运行中模块的 error 字段。
- ESM 与 TS 分支无缓存清理，重载不保证拿到新代码。
- 跳过分支静默，调用方无感知。
- 验证期间事件可拉起模块。
- 工厂函数副作用在验证阶段执行一次。
