# 场景：事件链式转发

模块收到事件后产生新事件，新事件再次经过完整比对，形成链式协作。

## 流程

1. 模块 A 收到 chat:receive，在 onEvent 中调用 sendEvent('chat:command')。
2. 核心按调用方把来源段拼进事件名（A:事件名段）。
3. dispatch：startIndex 命中先启动未运行模块；listenIndex 命中的运行模块逐个投递。记 event 日志，含转发名单。
4. 投递顺序为加载顺序，逐个等待完成；单点抛错仅记 error，继续投递其余。
5. 监听模块再产生新事件，在同一 await 链内深度优先完成。
6. sendEvent 返回时整条链已达成。

## 边界

- 投递串行无超时：一个 onEvent 悬挂，后续监听者与调用方全部阻塞（见 已知问题 6）。
- 无递归深度防护：监听自己产生的事件会栈溢出。
- 启动阻塞转发：start 永不返回，事件不投递、不记录（见 已知问题 2）。
- 事件丢弃不区分无人声明与未运行、未实现。
- 失败不熔断、副作用不回滚，下次同事件再试再报。
- event 日志先生成，不代表送达成功。
- 未 await 的派生事件异常成为未处理拒绝（见 已知问题 7）。
- 停机期间模块发事件抛错（见 已知问题 5）。
