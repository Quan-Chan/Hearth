# 模块生命周期

## 状态机

模块状态四个取值：stopped、starting、running、failed。

启动时间与失败原因不保存在状态中：module-start 与 error 日志带时间戳与详情。

## 启动流程

startModuleCore 的步骤：

1. 前置检查：已运行、启动中、禁用、超时锁定各自记 module-skip
2. startSeq 代数递增，状态置 starting
3. 从磁盘加载程序文件（每次启动都重载）
4. 构造 ModuleContext，等待 start() 返回
5. 成功：置 running，记 module-start
6. 抛错：置 failed，记 error

## 启动防护

三个机制处理异步启动的竞态：

- 启动代数（startSeq）：停止、配置更新使代数递增，启动完成后检查代数，发现已变则结果作废（不写运行状态，调用 stop 回收）——防止已停模块被迟到结果复活
- 启动尝试锁（inflightStart）：同一模块同时只允许一次启动尝试，防事件风暴重复拉起
- 启动超时与自动重试锁（startTimedOut）：超时只放弃等待（JS 无法终止函数），标记失败并锁定；手动、CLI、配置加载、配置更新、重启五种途径解锁，防止悬空调用堆积

## 重启

requestReload / reloadModule 的流程：

1. 加载并验证新代码（文件存在、清缓存加载、ESM 动态 import、工厂求值、导出必须是对象）
2. 验证失败：记 error，旧实例继续运行，返回 false
3. 验证通过：停止旧实例（数组注销），用已验证的 def 启动新实例，不重复加载

## 停机协议

core.stop() 的流程：

1. 置 stoppingFlag，冻结事件面（外部事件、定向信息、配置变更均拒绝）
2. 停止配置监听，冻结文件面
3. 对 starting 模块作废启动（代数递增、置 stopped、注销数组）
4. 对 running 模块并行执行关闭：调用 stop()，返回即已关闭，抛错仅记 error
5. 等待全部返回，超过 stopTimeoutMs 强制关闭并在 error 日志点名
6. 注销核心自身数组，复位标志，记 core-stop，关闭日志文件

停机不再广播关闭信号事件：停止的唯一入口是停止钩子，模块自行实现收尾逻辑。
