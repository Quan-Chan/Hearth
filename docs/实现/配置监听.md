# 配置监听

## 轮询

ConfigWatcher 以轮询方式监听模块文件夹，默认间隔 200ms，定时器 unref 不阻止进程退出。watch 选项关闭轮询，rescanModules 手动触发一次扫描。

## 变化检测

每轮对每个文件先比较 stat 指纹（mtimeMs、size、ctimeMs），指纹不变直接跳过；指纹变化才读取内容并计算 sha1，哈希变化才解析与回调。同内容只改时间的触碰不触发处理。

## 目录规则

只收集两层：模块文件夹顶层直接放置的 YAML，以及每个模块一个子文件夹内直接放置的 YAML。跳过 node_modules 与隐藏目录，收集顺序按文件名字母序。

## 容错

- 解析失败的 YAML：记 error，不更新指纹，下一轮重试（自愈）
- 被拒绝注册的文件（同名冲突）：不记账，每轮重新请求，持续可见直到问题修复
- 同名模块：模块名全局唯一，先注册者保留

## 热生效

配置更新只重载 YAML 本身：

- 更新模块注册与转发表（startEvents/listen 变化即时生效）
- 运行中的模块：刷新 ctx.config 引用，实例与代码不动
- 配置把 enabled 改为 false：停止运行中的模块

代码重载由模块自行发起（requestReload），配置更新不重载代码。
