# Connect-Core 需求

## 1. 软件形式

软件由核心与模块组成。核心的职责：

- 启动模块
- 在模块之间转发事件
- 提供模块共享数据

模块的组成：

- 模块是 YAML 配置与程序文件的组合
- YAML 声明身份、程序位置与事件关系四要素
- 程序文件可以是 CJS 对象、ESM 默认导出、返回对象的工厂函数三种形态
- 导出对象可包含四个可选钩子：启动 start、停止 stop、接收事件 onEvent、接收定向消息 onMessage
- 每次启动从磁盘重新加载程序文件

模块布局规则：

- 每个模块一个子文件夹，文件夹内放模块名相同的 YAML 与程序文件
- 顶层平铺放置同样被识别
- 只识别这两层，不递归更深目录

## 2. 模块注册与配置热加载

模块文件夹被核心持续监听，以下变化就地生效，无需重启：

- 新增 YAML 文件：注册模块
- 内容变化：更新模块的配置与转发表
- 删除文件：停止并移除模块

配置变化的应用规则：

- 更新只作用于 YAML 本身，运行中的模块实例与代码不变
- 模块随时读取新配置，自行决定何时应用
- 配置把启用开关改为关闭时，停止运行中的模块
- 解析失败的 YAML 记日志并在下轮重试，不影响核心与其他模块
- 模块名全局唯一，已有同名模块时新文件拒绝注册，被拒绝的文件持续重新请求直到问题修复
- 配置变化的识别采用双重校验（文件状态与内容哈希），仅触碰时间的操作不触发更新

## 3. 通信机制

模块之间的信息交换经三条通道：事件广播、定向消息、共享数组。

### 3.1 事件广播

事件的结构：



事件的传递规则：

- 事件即发即弃，无队列、无重试
- 同一事件对未运行模块是启动信号，对运行模块是工作指令
- 事件到达时先比对启动条件，再比对监听条件
- 监听者按加载顺序逐个收到事件，单个模块处理失败不影响其他模块
- 无人监听的事件记为事件丢弃
- 事件名匹配支持通配符：* 匹配任意字符序列，? 匹配单个字符

生命周期事件：

- core:startup：核心启动完成时发出，声明依赖该事件的模块自动启动

### 3.2 定向消息

模块可以向指定模块发送信息，中间经过核心。规则：

- 核心验证目标模块存在且运行，无效目标不传递
- 未实现 onMessage 的模块不收定向消息，发送方收到未送达结果
- 投递时把目标模块名替换为来源模块名
- 目标为核心时可寻址：作为管理指令入口，结果直接回传发起方
- 支持请求-应答：应答方直接回复发起方，多个请求方互不串扰

### 3.3 共享数组

模块可以把数组公开，其他模块可以拉取。规则：

- 公开的是数组对象引用，不拷贝
- 其他模块可以直接修改原数组内容，修改对所有持有者即时可见

- 取消公开仅拥有者可执行
- 公开数组的模块被关闭时，数组随之消失
- 数组的容量与持久化由使用方自行负责
- 数组操作不记录日志：数组是业务数据通道，可能高频读写，逐条记录会撑爆日志

## 4. 模块生命周期

### 4.1 状态

模块状态：停止、启动中、运行中、失败。启动时间与失败原因不保存在状态里：module-start 与 error 日志带时间戳，查日志即可。

对已运行模块的重复启动、对未运行模块的关闭、对禁用模块的操作记跳过日志。

### 4.2 启动

- 启动事件出现时，核心启动未运行且启用的模块
- 一次启动尝试未完成前，同一模块不接受再次启动
- 每次启动重新加载程序文件并调用启动钩子
- 启动钩子抛错：模块标记失败并记错误日志
- 启动钩子未在期限内返回：核心放弃等待并标记失败，该模块不再因事件自动重试；需人工或配置侧干预才能恢复
- 启动失败的模块可被手动启动或配置更新恢复

### 4.3 停止

- 停止单个模块：调用其停止钩子并等待返回，返回即已关闭
- 停止进行中的启动：该次启动作废，其启动钩子的副作用照常发生

### 4.4 重启

模块替换程序文件后可请求重启自身。规则：

- 核心先验证新代码可加载
- 验证失败：旧实例继续运行，请求方收到失败结果
- 验证通过：停止旧实例，用已验证的代码启动新实例
- 状态保存与恢复是模块的职责，核心不迁移任何状态

## 5. 核心生命周期

### 5.1 启动

启动核心等于启动整个软件：

1. 扫描模块目录
2. 注册全部模块配置并建立转发表
3. 发出 core:startup
4. 启动事件匹配的模块自动启动

提供两种入口：只构造不启动，构造并立即启动。

### 5.2 停止

停止核心的流程：

1. 停止配置监听
2. 调用各运行模块的停止钩子并等待返回
3. 全部返回即完成

规则：

- 等待有总时限，超时强制关闭并记录未返回的模块
- 停机期间新事件、定向消息、配置变更均被拒绝
- 停机中调用发送接口会收到错误

### 5.3 代码重载

- 启动时重新加载程序文件，模块重启后获得最新代码
- 配置更新不重载代码，代码重载由模块发起

## 6. 失败处理与进程守卫

- 核心对钩子的调用各自独立捕获异常，单个模块失败不影响其他模块与核心
- 模块私下的未处理异步失败默认按运行时的默认行为处理
- 可开启进程守卫：捕获未处理的异步失败与未捕获异常，仅记日志、进程继续
- 失败可通过模块状态与日志查询

## 7. 日志

日志只记录核心框架自己干的事情。条目结构：

- 每条日志包含三项信息：日志类型、日志来源、日志信息
- 附加结构化字段：事件名、数据、转发名单、原因、错误、文件名、清理数组

存储与展示：

- 日志是连续的时间线，按发生顺序排列，按类型或类别过滤
- 双层存储：内存保留最近若干条，完整落盘到 JSONL 文件
- 落盘按天与大小分文件轮转，进程重启后沿用当前文件
- 落盘内容完整，展示层对超长内容缩短并标注原始长度
- 数组操作不记录日志
- 模块可主动写日志，类型为模块日志
- 可把日志同步输出到控制台

日志类型包括：

1. 核心启停：核心启动、核心关闭
2. 事件处理：事件转发、事件丢弃
3. 模块生命周期：启动模块、关闭模块、跳过启停、启动超时、重启
4. 配置热加载：加载配置、更新配置、移除配置
5. 模块日志：模块显式请求记录的日志
6. CLI 指令：指令执行记录
7. 错误：启动失败、事件处理失败、配置解析失败等

## 8. 命令行界面

提供可选的命令行界面模块，让框架的行为可见可操作。

指令：

- event：产生一个事件
- start：启动模块
- stop：停止模块
- send：定向发送事件，支持广播与多目标
- state：查询模块与公共数组
- exit：先把结果交付再关闭核心
- log：查看日志时间线，按过滤词与条数



## 9. 宿主集成接口

宿主可用的能力：

- 创建与启动核心
- 查询：模块列表、单模块状态、数组清单、数组拥有者、索引状态
- 管理：启动模块、停止模块、重启模块、手动重扫、发送事件、定向发送

核心可配置项：

- 模块目录、日志文件路径、监听开关
- 轮询间隔、默认模块启动超时、停机时限、日志内存条数
- 控制台输出、进程守卫

## 10. 技术栈与工程要求

语言采用 TypeScript，运行时采用 Node.js。

需要构建大量测试用例来验证框架。测试思路：

1. 分析框架有什么作用
2. 分析哪些软件会用到这些功能
3. 通过构建这些软件来进行测试

应提供用户可控制的演示软件，让框架的行为可见可操作。

## 11. 协作结构

- 模块间的依赖关系通过事件在运行时涌现，模块之间互不知晓
- 模块间的协作采用事件信号与共享数组
- 模块仍可用文件、网络、子进程等任何外部通道
- 用一个极小的中心文件管理大量插件
