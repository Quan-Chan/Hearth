# Doc Writing Requirements

## Prohibited

- No bold, no emphasis of any form
- No evaluative words
- No recommendations
- No extremes, no oversimplification, no over-complication
- No twists and suspense, no marketing tone
- No self-aggrandizement, no self-justification
- No over-explaining a basic concept
- No explaining in a place that is not the place for it
- Types, options, and other explanations go in the body text
- Do not explain every line of code
- Do not assume the reader holds a bias and clarify concepts for it
- No self-vindication, no low self-esteem, no ingratiation
- No meta information, no traces of analysis (sources, methods, data)
- State necessary information directly as header information, without promotion

## Discouraged words

拆解 (break down), 兜底 (fallback), 优雅 (elegant), 流水 (flow), 约定 (convention), 语义 (semantics), 精通 (master), 一步步 (step by step), 稳稳 (steadily), 只记 (only record), 一律 (uniformly), 精准 (precise), 原子 (atomic), 准则 (criterion), 原则 (principle)

## Discouraged sentence patterns

1. Not... but...
2. Not... ...
3. ..., but...
4. ... and that's it (as soon as...)

## Requirements

- No metaphors
- No personification
- High information density
- Code examples go in code blocks
- Inline code and paths use backticks
- Write only the content of the software itself
- Content that will be deleted does not enter the document
- Defaults, behavior, order, and names must be accurate
